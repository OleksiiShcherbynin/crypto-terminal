# Crypto Terminal — дизайн-документ

Дата: 2026-10-28
Статус: черновик, ждёт утверждения владельца
Русская версия документа `2026-10-28-crypto-terminal-design.md`. При расхождении
источником истины считается английская версия.

## 1. Замысел

Криптотерминал для paper-trading, целиком работающий в браузере на живых
котировках Binance. Это **портфолио-проект** для откликов на frontend-вакансии.
Его задача — за пять минут, пока нанимающий инженер листает репозиторий и
кликает по живой ссылке, доказать уверенное владение:

- TypeScript (strict),
- React с хуками,
- Redux (Redux Toolkit),
- **redux-saga** — для настоящей асинхронной работы, а не «загрузил список по клику»,
- библиотекой стилей (Tailwind).

Saga — главный акцент. Каждая сага в приложении существует потому, что она
нужна продукту, и каждая показывает свою грань библиотеки: event channel,
переподключение с backoff, отмена, гонки, долгоживущие наблюдатели на сущность,
отложенное сохранение.

## 2. Цели, не-цели, анти-цели

### Цели

1. Рецензент открывает живой URL и через несколько секунд видит движущиеся
   цены: без настройки, без ключа, без аккаунта.
2. Он может купить, продать, выставить лимитную заявку, поставить алерт,
   перезагрузить страницу — и всё на месте.
3. Слой саг читается как production-код: типизирован, протестирован, каждый
   паттерн очевиден из имён файлов и README.
4. Интерфейс выглядит как торговый терминал, который кто-то проектировал, а не
   как демо компонентной библиотеки.
5. Репозиторий объясняет себя сам: английский README со скриншотами, раздел
   про архитектуру и таблица «фича → эффекты саги».

### Не-цели

- Никакого бэкенда, авторизации, реальных денег, ключей биржи.
- Один пользователь, одно устройство. Синхронизации между устройствами нет.
- Нет стакана, маржи, шортов, комиссий, проскальзывания.
- Нет редактирования списка пар; список — фиксированная константа.
- Мобильная версия пригодна, но вторична. Основная сцена — десктопное окно
  шириной ≥ 1280 px.

### Анти-цели (провал, даже если всё работает)

- Сага, которую можно заменить на `createAsyncThunk` без потерь.
- Вёрстка, которая читается как «шаблон админки».
- Приложение, которое выглядит сломанным, когда поток биржи упал. Потеря
  соединения должна быть видна, объяснена и самовосстанавливаться.
- Повреждённое состояние после перезагрузки (отрицательные балансы,
  фантомные заявки, двойные исполнения после восстановления).
- Шторм перерисовок: 25 тикеров на частоте обновлений Binance не должны
  тормозить страницу.

## 3. Ограничения

- **Источник данных:** публичные market-data эндпоинты Binance, без ключа.
  - Combined-stream WebSocket: `wss://data-stream.binance.vision/stream?streams=...`
    (хост только для рыночных данных). Запасной хост: `wss://stream.binance.com:9443`.
  - REST для истории свечей: `https://data-api.binance.vision/api/v3/klines`
    (запасной `https://api.binance.com`). CORS на этих публичных эндпоинтах открыт.
  - Используемые стримы: `<symbol>@miniTicker` для каждой пары из списка
    (последняя цена, open/high/low/volume за 24 ч); `<symbol>@kline_<interval>`
    только для выбранной пары.
  - Важные лимиты: одно соединение держит до 1024 стримов; не более 5
    сообщений subscribe/unsubscribe в секунду; сервер рвёт соединение через
    24 ч и шлёт ping каждые 20 с (браузер отвечает pong сам).
  - Некоторые сети и регионы блокируют хосты Binance. Доступность всех
    четырёх хостов (оба REST, оба WebSocket) с машины владельца проверена
    2026-10-28: первое сообщение тикера пришло за 2 с на обоих сокетах.
    Запасной биржи в scope нет: если регион рецензента блокирует Binance,
    приложение показывает состояние Offline, а README называет это
    ограничение. Клиент сокета сначала пробует основной хост, после двух
    подряд неудачных попыток переключается на запасной и дальше чередует
    (исполнитель может подстроить).
- **Хостинг:** статика, GitHub Pages (Vite `base` = имя репозитория) через
  GitHub Actions. Vercel допустим, если с Pages будет неудобно.
- **Окружение:** Windows 11, PowerShell 5.1, Node 24, npm 11. Скрипты в
  `package.json` не должны полагаться на `&&` при запуске через PowerShell;
  использовать цепочки npm-скриптов или `npm-run-all`.
- **Язык:** интерфейс, код, комментарии, README — на английском.

## 4. Продукт

### 4.1 Экран

Один экран, без роутера. Три области на десктопе:

```
┌──────────────────┬──────────────────────────────┬───────────────────┐
│ Market           │ BTC/USDT  67,412.50  +1.84%   │ Trade             │
│ [search…]        │ [1m][15m][1h]                 │ [Buy] [Sell]      │
│ BTC/USDT 67,412  │                               │ Market | Limit    │
│ ETH/USDT  3,512  │        candlestick chart      │ Qty [____] 25 50  │
│ …                │                               │ Price [____]      │
│                  │                               │ Cost  1,234 USDT  │
│                  │                               │ [ Buy BTC ]       │
│                  │                               │ Balance 8,765 USDT│
├──────────────────┴──────────────────────────────┴───────────────────┤
│ Positions | Open orders | History | Alerts              ● Live       │
│ BTC  0.0150  avg 66,900  value 1,011  P&L +7.69 (+0.77%)            │
└─────────────────────────────────────────────────────────────────────┘
```

Ниже 1280 px три области складываются в столбец (список пар, затем график с
формой торговли, затем нижняя панель вкладками). Тосты появляются справа снизу.

### 4.2 Список пар

- ~25 пар к USDT, фиксированная константа (BTC, ETH, BNB, SOL, XRP, ADA, DOGE,
  AVAX, DOT, LINK, MATIC, LTC, TRX, UNI, ATOM, NEAR, APT, ARB, OP, FIL, ETC,
  XLM, ICP, SUI, PEPE — исполнитель может скорректировать по тому, что Binance
  реально торгует на момент сборки).
- Колонки: пара, последняя цена, изменение за 24 ч в %, объём за 24 ч
  (компактно).
- Ячейка цены на мгновение вспыхивает зелёным/красным при тике вверх/вниз.
- Текстовый фильтр сужает список на клиенте (чистый селектор, без саги:
  фильтрация 25 строк синхронна).
- Клик по строке выбирает пару; выбор подсвечен и сохраняется.
- Сортировка по колонкам — приятное дополнение, на усмотрение исполнителя.

### 4.3 График

- Свечной график выбранной пары; интервалы 1m, 15m, 1h.
- При выборе пары или смене интервала: загрузить последние ~300 свечей через
  REST, затем обновлять последнюю свечу из kline-стрима.
- Библиотека: `lightweight-charts` (TradingView, Apache-2.0). Это естественный
  вид для терминала, и она умеет потоковые обновления. Моё решение;
  исполнитель может заменить библиотеку, только если замена поддерживает живое
  обновление свечей.
- Если история не загрузилась, график показывает «history unavailable» и
  рисует только по живым свечам; торговлю это не блокирует.

### 4.4 Торговля

- Стартовый баланс: 10 000 USDT (виртуальных) при первом визите. Действие
  «Reset portfolio» в шапке восстанавливает его (с подтверждением) и очищает
  заявки, алерты и историю.
- Сторона: Buy / Sell. Тип: Market / Limit.
- Количество в базовом активе, кнопки 25/50/75/100 % (от доступных USDT для
  покупки, от удерживаемого количества для продажи). Форма вживую показывает
  расчётную стоимость или выручку в USDT.
- **Рыночный ордер**: форма диспатчит `marketOrderRequested`; `tradeSaga`
  берёт через `select` текущую последнюю цену и статус соединения, валидирует
  и диспатчит `orderFilled` (или `orderRejected` с причиной). Редьюсеры
  никогда не читают чужие слайсы ради цены.
- Рыночные ордера **принимаются только при статусе Live**. В состояниях
  Reconnecting и Offline кнопка Buy/Sell выключена, форма объясняет почему.
  Лимитные заявки и алерты можно ставить офлайн; они сопоставляются, когда
  живые тики возобновятся.
- **Лимитная заявка** хранится как открытая, за ней следит сага. Buy-лимит
  исполняется, когда последняя цена ≤ лимита; sell-лимит — когда ≥ лимита.
  Исполнение по цене лимита. Средства резервируются при выставлении (USDT для
  покупки, базовый актив для продажи), доступный баланс их не включает. Отмена
  снимает резерв.
- Лимитная заявка не с той стороны рынка **отклоняется на валидации**:
  buy-лимит должен быть ниже текущей цены, sell-лимит — выше. Так «исполнение
  по цене лимита» остаётся честным. Офлайн живой цены нет, поэтому проверка
  использует последнюю известную цену, а форма показывает, что она устарела.
- Валидация: количество > 0, достаточно средств/количества, цена лимита > 0 и
  с правильной стороны. Ошибки показываются inline, отправка выключена.
- Исполнение (рыночное или лимитное) показывает тост.

### 4.5 Портфель

- Позиции: по активу — количество, средняя цена входа, текущая стоимость,
  нереализованный P&L в USDT и %. Пересчёт на каждой пачке цен через
  мемоизированные селекторы.
- Шапка показывает общий капитал (USDT + позиции по последней цене) и
  реализованный P&L.
- Учёт по средней цене. Реализованный P&L накапливается при продажах.
- История сделок: время, пара, сторона, тип, количество, цена, сумма. Новые
  сверху.
- Денежная арифметика не должна оставлять «пыль» и отрицательные значения.
  Исполнитель выбирает между decimal-библиотекой (`big.js`) и дисциплиной
  округления; требование: позиция, проданная на 100 %, исчезает, а баланс
  никогда не уходит ниже нуля из-за округления.

### 4.6 Алерты

- «Уведомить, когда ПАРА выше / ниже X». Одноразовый: срабатывает один раз,
  затем помечается сработавшим со временем.
- Семантика — **проверка уровня**, а не пересечения: алерт срабатывает на
  первом живом тике с ценой ≥ X (выше) или ≤ X (ниже). Создание алерта, чьё
  условие уже выполнено, отклоняется на валидации («price is already above
  X»). Алерт, восстановленный из хранилища, чей уровень был пройден, пока
  вкладка была закрыта, срабатывает на первом живом тике после перезагрузки;
  это желаемое поведение, README об этом говорит.
- Срабатывание показывает тост и оставляет алерт в списке как сработавший.
- Алерт можно удалить в любой момент.
- Тосты: справа снизу, автозакрытие через ~6 с, ручное закрытие.

### 4.7 Статус соединения

- Индикатор в нижней панели: **Live** / **Reconnecting (attempt n)** /
  **Offline**.
- Когда поток упал, цены остаются на экране, но приглушены, а форма торговли
  предупреждает, что исполнение может задержаться. Исполнений по устаревшим
  ценам не бывает (заявка сопоставляется только с тиками, пришедшими при
  живом соединении).

### 4.8 Сохранение

- `localStorage`, один версионированный ключ (`crypto-terminal:v1`).
- Сохраняются: баланс, позиции, открытые заявки, сделки, алерты, выбранная
  пара и интервал. Не сохраняются: тикеры, свечи, состояние соединения, тосты.
- Восстановление при запуске до старта саг. Несовпадение версии схемы
  сбрасывает в значения по умолчанию, а не роняет приложение.
- **Несколько вкладок — задокументированное ограничение**, а не
  поддерживаемый случай: каждая вкладка запускает своих наблюдателей,
  побеждает последняя запись. Приложение слушает событие `storage` и, когда
  другая вкладка записала ключ, показывает неблокирующий баннер «Changed in
  another tab, reload to sync» и прекращает сохранять из этой вкладки до
  перезагрузки. Без блокировок, без BroadcastChannel.

## 5. Архитектура

### 5.1 Стек (решено)

| Задача | Выбор |
|---|---|
| Сборка | Vite, TypeScript `strict`, ESLint, Prettier |
| Состояние | Redux Toolkit slices, типизированные хуки, мемоизированные селекторы |
| Побочные эффекты | redux-saga (вся асинхронная и временная логика здесь) |
| Стили | Tailwind CSS v4, без компонентной библиотеки |
| График | lightweight-charts |
| Тесты | Vitest, redux-saga-test-plan, React Testing Library |
| CI/CD | GitHub Actions: lint, test, build, деплой на Pages |

### 5.2 Структура по фичам

```
src/
  app/            store, rootSaga, типизированные хуки, граница persistence
  features/
    market/       слайсы tickers и connection, сага стрима, список пар
    chart/        слайс candles, сага графика
    portfolio/    слайс balance, positions, trades; селекторы
    orders/       слайс открытых заявок, сага-наблюдатель заявок
    alerts/       слайс алертов, сага-наблюдатель алертов
    notifications/ слайс тостов, сага тостов
  services/
    binance/      фабрика WebSocket-клиента, REST-клиент, парсеры сообщений
  ui/             общие примитивы (Button, Input, Tabs, Panel, Toast)
```

Каждая фича владеет своим слайсом, сагами, селекторами, компонентами и тестами.
Общение между фичами — только через экшены (например, сага заявок диспатчит
`orderFilled`, редьюсер портфеля его обрабатывает).

### 5.3 Саги и что каждая демонстрирует

| Сага | Делает | Эффекты, которые показывает |
|---|---|---|
| `marketStreamSaga` | Открывает один combined-stream сокет на все тикеры; парсит сообщения; батчит тики и диспатчит `tickersUpdated` не чаще ~4 раз/с; ведёт статус соединения; переподключается с экспоненциальным backoff (1 с → потолок 30 с) при закрытии или ошибке; 30 с тишины считает мёртвым соединением | `eventChannel` со sliding-буфером, `race` (сообщение vs таймаут тишины vs `stop`), `delay`, цикл в духе `retry`, очистка через `cancelled()` с закрытием сокета |
| `chartSaga` | При смене пары или интервала: отписаться от прежнего kline-стрима, отменить незавершённую загрузку истории, загрузить историю, подписаться на новый kline-стрим, применять живые обновления свечи | `takeLatest`, `call` с отменой, `fork`, `cancelled()`, сообщения subscribe/unsubscribe через общий сокет |
| `tradeSaga` | Обрабатывает `marketOrderRequested`: берёт последнюю цену и статус соединения, валидирует, диспатчит `orderFilled` или `orderRejected` | `takeEvery`, `select`, `put` |
| `orderWatcherSaga` | Один форкнутый наблюдатель на каждую открытую лимитную заявку: создаётся при выставлении и пересоздаётся при запуске для восстановленных заявок; ждёт тик, пересекающий лимит, в гонке с отменой; диспатчит `orderFilled` | `fork` на сущность, `take` с предикатом, `race` (исполнение vs отмена), `select` |
| `alertWatcherSaga` | Та же форма, что у заявок, для ценовых алертов; при срабатывании диспатчит `alertTriggered` и `toastPushed` | `fork`, `take`, `race`, `put` |
| `toastSaga` | Автозакрытие каждого тоста через задержку, если не закрыт вручную | `takeEvery`, `race` (`delay` vs экшен закрытия) |
| `persistenceSaga` | Записывает сохраняемую часть состояния после изменения любого из сохраняемых слайсов, с debounce | `debounce` по паттерну экшенов, `select` |

Правила:

- Никакой временной логики (`setTimeout`, циклы переподключения) вне саг.
- Никакой бизнес-логики (сопоставление исполнений, P&L) внутри компонентов.
- Исполнение или алерт сопоставляется только с тиками, полученными по живому
  соединению, никогда с восстановленным состоянием, поэтому перезагрузка не
  может исполнить заявку дважды.
- Сокетом владеет клиент в `services/binance` с методами
  `subscribe(streams)` / `unsubscribe(streams)`; `marketStreamSaga` управляет
  его жизненным циклом, `chartSaga` только подписывается и отписывается от
  kline-стрима через него. После переподключения клиент заново подписывается
  на все стримы, которые держит, включая выбранный kline-стрим.
- У каждой саги есть тесты на `redux-saga-test-plan`, сокет и REST-клиент
  подставляются моками. У редьюсеров юнит-тесты. Ключевые компоненты
  (валидация формы торговли, вспышка строки, тост) покрыты RTL-тестами.

### 5.4 Производительность

- Тики батчатся в саге; слайс тикеров обновляется один раз на пачку.
- Строки списка мемоизированы и подписаны на свой символ через селектор:
  один тик перерисовывает одну строку.
- Позиции и капитал — мемоизированные селекторы, ключ — пачка тикеров.

## 6. Визуальное направление

Tailwind, только тёмная тема. Плотно, спокойно, цифрово. Замысел: «инструмент,
который трейдер держит открытым весь день», а не промо-страница.

- Фон почти чёрный, панели чуть светлее; один акцентный цвет для выделения и
  основных кнопок; зелёный и красный только для движения цены и P&L.
- Числа моноширинным шрифтом или с табличными цифрами
  (`font-variant-numeric: tabular-nums`); текст интерфейса — нейтральный
  гротеск.
- Панели разделены тонкими линиями, не тенями. Минимум хрома, никаких карточек
  внутри карточек.
- Вспышка цены: короткая подсветка фона, которая гаснет, без сдвига вёрстки.
- Навык frontend-design применяется на этапе реализации для подбора
  типографики и точной палитры; этот раздел фиксирует только направление.

## 8. Форма реализации (для плана)

Владелец хочет, чтобы код писали несколько агентов. Поэтому план сначала
фиксирует контракты, потом распараллеливает:

1. Скаффолд и контракты: проект Vite, Tailwind, store, формы состояния слайсов
   и action creators, типы сообщений Binance, интерфейсы сервисов. Один агент,
   последовательно.
2. Параллельно: (а) слайсы, селекторы, саги и их тесты; (б) UI-компоненты
   по контрактам с замоканными данными store.
3. Интеграция, README, CI, деплой, финальное ревью.

## 9. На усмотрение исполнителя

- Точная разбивка на компоненты внутри каждой фичи.
- Размер загрузки истории свечей, детали слияния свечей.
- Правила форматирования чисел по парам (точность цены, компактный объём).
- Выбор между decimal-библиотекой и дисциплиной округления (§4.5).
- Сортировка колонок в списке пар.
- Раскладка тестовых файлов и дизайн фикстур.
- Точные константы backoff, интервал батча, таймаут тишины (числа в §5.3 —
  значения по умолчанию, не требования).

## 10. Решения Claude, а не владельца

Перечислены, чтобы владелец мог отменить любое из них при чтении:

- Tailwind вместо Material UI — **выбор владельца** (2026-10-28).
- Без роутера, один экран с нижней панелью на вкладках.
- Фиксированный список пар, без редактирования.
- Исполнение по цене лимита, резерв средств при выставлении, без комиссий и
  проскальзывания, только лонг.
- Фильтр списка пар — селектор, а не сага.
- `lightweight-charts` для графика; интервалы 1m / 15m / 1h.
- Хосты Binance `data-stream.binance.vision` / `data-api.binance.vision` как
  основные, `stream.binance.com` / `api.binance.com` как запасные.
- Только тёмная тема.
- GitHub Pages как цель деплоя по умолчанию; владелец пушит и включает Pages
  вручную (на машине нет `gh`).
- Рыночные ордера только при Live, через `tradeSaga`.
- Лимитные заявки не с той стороны и уже выполненные алерты отклоняются на
  валидации; алерты — проверка уровня, восстановленные алерты могут
  сработать на первом живом тике.
- Несколько вкладок: задокументированное ограничение с баннером «reload to
  sync».
- Запасной хост Binance после двух неудачных попыток; второй биржи нет.
- Аккаунт GitHub для живой ссылки: `OleksiiShcherbynin` (подтверждён
  владельцем 2026-10-28).
